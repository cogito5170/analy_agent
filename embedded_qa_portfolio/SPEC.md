## 1. 요건 커버리지 요약

지원자 답변 반영: 하드웨어 없음(가상 우선, 8주차에 저가 키트 구입 여부 결정), 대상 BMS, 학교 MATLAB/Simulink 사용 가능.

분류 기준

## 2. 시스템 개요

**무엇을 만드나.** 4직렬 셀 배터리 팩을 관리하는 BMS 펌웨어를 C로 작성한다 [A01, A12]. 이를 PC에서 플랜트 모델과 폐루프로 연결하는 SIL 리그를 만든다 [A07, A13]. 요구사항부터 시험·결함 보고까지 추적되는 자동 검증 파이프라인을 CI로 돌린다 [A03, A09, A14].

**왜 BMS인가 [A12].**
- 셀 전압·온도·전류를 저전압 신호나 모델로 안전하게 모사할 수 있다.
- 과전압·저전압·과온·과전류 보호, 컨택터 차단, 진단 고장 코드(DTC)처럼 시험할 안전 기능이 분명하다.
- 인버터·OBC는 고전력 하드웨어와 실시간 제어 모델이 필요해 개인 비용과 위험이 크다.

### 구성도 — 기본 구성 (1~12주, 하드웨어 없음)

```text
 ┌────────────────────────── PC / GitHub Actions runner ───────────────────────────┐
 │                                                                                 │
 │  ┌──────────────────────┐  sensor values   ┌────────────────────────────────┐  │
 │  │ Plant model (Python) │ ───────────────▶ │ BMS firmware (C, host build)   │  │
 │  │  4S equivalent-circuit│  (virtual AFE)  │  libbms.so                     │  │
 │  │  + thermal model     │ ◀─────────────── │  measurement · protection SM   │  │
 │  │  ▲ back-to-back check│  contactor state │  contactor · CAN · UDS · DTC   │  │
 │  └──┼───────────────────┘                  └───────────────┬────────────────┘  │
 │     │ CSV                                     CAN frames   │ (lockstep, 1 ms)  │
 │  ┌──┴───────────────────┐                  ┌───────────────▼────────────────┐  │
 │  │ Simulink model       │                  │ SIL harness (Python, ctypes)   │  │
 │  │ (school license,     │                  │  fault injection · sim clock   │  │
 │  │  run outside CI)     │                  │  python-can virtual bus        │  │
 │  └──────────────────────┘                  └───────────────┬────────────────┘  │
 │                                                            │                   │
 │                                            ┌───────────────▼────────────────┐  │
 │                                            │ pytest suites · cantools (DBC) │  │

 └─────────────────────────────────────────────────────────────────────────────────┘
```

### 구성도 — 선택 구성 (8주차 관문에서 구입을 결정한 경우만)

```text
 ┌──────────── PC ────────────┐     CAN (500 kbit/s)     ┌────── DUT ───────────────┐
 │ same pytest suites         │ ◀──────────────────────▶ │ STM32 board (TODO model) │
 │ python-can (real bus)      │   USB-CAN adapter (TODO) │ + CAN transceiver (TODO) │
```

### C1. 요구사항과 추적 매트릭스 — Must
- **근거:** [A03, A19, A11, A10]
- **입력:** HARA-lite 결과(4절 D3), BMS 기능 정의
- **출력:** `requirements/*.yaml`, `reports/trace_matrix.{md,csv}`
- **핵심 기능**
  1. 요구사항을 계층으로 관리한다: 안전 목표(SG) → SW 요구사항(SWR) → 테스트 케이스(TC). 각 항목은 ID, 문장, 근거(parent), 검증 방법(test / review / analysis), 우선순위를 가진다.
  2. 요구사항 품질 규칙을 자동 검사한다. 모호어 금지, 수치 기준 필수, parent 누락 금지.
  3. TC 코드의 `@verifies("SWR-012")` 표기를 읽어 양방향 추적 매트릭스를 생성한다. 검증되지 않은 요구사항과 요구사항이 없는 TC를 모두 보고한다.
- **완료 기준:** SWR 30개 이상, 그중 `test` 방법 SWR의 100%가 TC 1개 이상에 연결, 고아 TC 0개, CI에서 매트릭스 자동 생성

### C2. BMS 펌웨어 (DUT) — Must
- **근거:** [A01, A12, A05, A17]
- **입력:** 셀 전압 4개, 온도 2개, 팩 전류(가상 AFE 인터페이스), CAN 수신(VCU 명령, UDS 요청)
- **출력:** 컨택터 명령, CAN 송신(상태·셀 전압·고장), DTC 저장소
- **핵심 기능**
  1. HAL 분리 구조: `app/`(하드웨어 독립)과 `hal/host`, `hal/stm32`(TODO) 두 구현
  2. 측정 처리: 범위 검사(신호 고장 판정), 이동 평균
  3. 보호 상태 머신: INIT → STANDBY → CLOSED → FAULT. 과전압·저전압·과온·저온·과전류를 디바운스(N회 연속) 후 판정하고 컨택터를 차단
  4. SOC 추정: 전류 적산 방식. 시험 목적상 정확도보다 동작 검증에 초점
  5. CAN: 주기 송신, VCU 명령 수신 타임아웃 감지, 메시지 카운터·체크섬 검사(E2E 보호 개념)
  6. UDS: ISO-TP(단일·다중 프레임), 0x10, 0x3E, 0x22(DID 5개), 0x19 sub 0x02, 0x14, NRC 응답
  7. DTC: 고장별 상태 바이트(testFailed, confirmedDTC 비트)
- **완료 기준:** `-Wall -Wextra -Werror`로 경고 0개 빌드, 동적 메모리 미사용, 10 ms 태스크 1회 실행이 호스트에서 결정적(같은 입력이면 같은 출력)

### C3. 플랜트 모델 — Must (Python), Should (back-to-back)
- **근거:** [A13, A02, A07]
- **입력:** 전류 프로파일, 초기 SOC, 주변 온도
- **출력:** 셀 단자 전압 4개, 셀 온도, 팩 전류
- **핵심 기능**
  1. 해석적 레퍼런스(Analytic reference): 사용자 결정(10-09)에 따라 Simulink 모델을 대체. 전류가 조각 단위로 일정한 구간에 대한 정확한 해석해를 별도 코드로 작성
  2. 10 ms 이산 Python 모델을 CI용으로 둔다 (Simulink 모델은 라이선스 확인 후 TODO)
  3. back-to-back: 같은 전류 프로파일 3종에 대한 두 모델(이산 Python과 해석적 레퍼런스)의 출력을 CSV로 비교
  4. 결함 주입 지점: 셀 단락·개방에 해당하는 전압 고착, 센서 오프셋, 온도 급상승
- **완료 기준:** 3개 프로파일에서 두 모델의 셀 전압 차이 최대값이 허용 기준(가정: 5 mV) 이하이고, 결과 CSV와 비교 리포트가 저장됨.

### C4. SIL 리그 (가상 HIL) — Must
- **근거:** [A07, A09, A02]
- **입력:** 시나리오(시간별 전류·결함 주입 이벤트)
- **출력:** 시뮬레이션 트레이스(신호·CAN 프레임·상태), 증거 파일
- **핵심 기능**
  1. 펌웨어를 공유 라이브러리로 빌드해 ctypes로 불러온다. 1 ms 단위 lockstep 시뮬레이션 시계를 쓴다
  2. 결함 주입 API: `inject(fault, at_ms, duration_ms)`. 대상은 센서 값, CAN 메시지 누락·지연·손상, 전류 급변
  3. 펌웨어가 송신한 CAN 프레임을 python-can 가상 버스에 실어 시험 코드가 실제 버스와 같은 API로 읽게 한다
  4. 시험 하나가 끝날 때마다 트레이스를 `evidence/<TC-ID>/`에 저장한다
- **완료 기준:** 결함 시나리오 15종 이상 자동 실행, 같은 시나리오 반복 실행 시 결과가 비트 단위로 동일

### C5. CAN 통신 정의와 분석 도구 — Must

  2. 트레이스 분석기: 메시지별 주기 통계(평균·최대 지터), 타임아웃, DLC 오류, 카운터 불연속 검출
  3. 펌웨어의 C 신호 정의와 DBC가 어긋나지 않는지 CI에서 검사(하나의 원본에서 생성하거나 대조)
- **완료 기준:** 모든 송신 메시지의 주기 요구사항이 SIL 트레이스로 검증되고, DBC와 C 정의 불일치를 검출하는 검사가 CI에 있음

### C6. UDS 진단 — Must (0x27은 제외)

  3. 보호 고장 발생 → DTC 저장 → 0x19 조회 → 0x14 삭제 → 재발 확인의 시나리오 시험
- **완료 기준:** 구현한 서비스마다 긍정·부정 응답 TC 각 1개 이상, 다중 프레임 응답 시험 통과

### C7. 자동 시험 프레임워크 — Must

  4. JUnit XML과 증거 링크를 담은 HTML·Markdown 결과 리포트
- **완료 기준:** SIL에서 TC 60개 이상 실행, 전체 실행 10분 이내, 실패 시 재현 명령과 증거 경로가 리포트에 남음

- **완료 기준:** `app/` statement 90% 이상·branch 80% 이상, cppcheck error 0건, 모든 일탈에 사유 기록

### C9. CI 파이프라인과 운영 자동화 — Must (CI), Should (야간·상태 점검)

### C12. 빌드 환경과 빌드 지표 — Must (컨테이너·재현성·빌드 시간), Should (불안정 비율·버전 삽입)

- **완료 기준:** CI에서 컨테이너 빌드와 ARM 빌드가 녹색이고, 재현성 검사가 통과하며, 실행마다 `metrics.json`이 아티팩트로 남음

| 10 | 야간 회귀·상태 점검(A15), 커버리지 보강 | C9 완료 | 10 | branch 커버리지 80% 이상, 야간 실행 시작 |
| 11 | (키트 있음) STM32 이행·실측·SPC / (키트 없음) 버퍼: 미해결 결함·문서 보완 | C11, D9 또는 보완 | 10 | 계획한 범위 완료 |
| 12 | SVP 최종, README·포트폴리오 정리, 면접 대응표 수치 기입 | 최종 저장소 | 10 | 9절 검토 체크리스트 통과 |

5절 프로젝트 외 준비(ISTQB 학습 등)는 이 120시간에 포함하지 않는다.
