# 세계관 기반 다매체 예술 SDK — 스펙 v0.1 (가칭: World SDK)

> 목적: 작가가 자기 **세계관**을 한 번 정의하면, 그림·3D·건축·사운드·인터랙션·물리 작품 등
> 어떤 매체로든 그 세계관을 일관되게 펼칠 수 있게 하는 SDK와 그 위의 도구.
> 미니멀부터 화려함까지 어떤 미학도 시스템의 기본값이 되지 않는다.
>
> 상태: 초안. **작가 인터뷰(7절) 결과로 요구사항을 고친다.** 인터뷰 전의 요구사항은 모두 가설이다.
> 표기: `[W-01]` 등은 이 문서의 요구사항 ID. `TODO`는 확인되지 않은 사실.

## 1. 설계 원칙

| # | 원칙 | 뜻 |
|---|---|---|
| P1 | 미학은 코드가 아니라 데이터에 | 시스템 코드에 특정 스타일이 없다. 스타일별 함수 금지. 모든 미적 선택은 세계관 데이터에 |
| P2 | 스타일은 축으로 | "미니멀 ↔ 화려함"은 여러 축(밀도, 색, 형태, 질감, 소리, 움직임, 서사)의 조합. 축은 확장 가능 |
| P3 | 섞고, 갈래 내고, 변형한다 | 세계관 합성(비율), 복제 후 수정(관계 기록), 시간에 따른 변형 경로 |
| P4 | 생성 방식도 스펙트럼 | 절차적(정확·통제), AI(풍부·의외), 혼합, 작가 직접 입력을 상황에 맞게 |
| P5 | 모든 단계에 탈출구 | 결과 직접 수정, 자기 에셋 가져오기, 규칙 깨기, 코드로 대체 |
| P6 | 매체는 플러그인 | 새 매체를 추가해도 핵심 코드는 바뀌지 않는다 |
| P7 | 작가가 소유하고 통제 | 세계관·학습 데이터는 작가 소유, 기본 비공개. 생존 작가 화풍 모방 기능은 기본 제공하지 않음 |

## 2. 사용자

| 사용자 | 쓰는 것 |
|---|---|
| U1 크리에이티브 코더 | SDK 직접 사용 (Python·JavaScript API, 노트북, 플러그인 작성) |
| U2 코드를 쓰지 않는 작가 | SDK로 만든 앱 (세계관 편집기, 작업 흐름 편집기, 웹 플레이어) |
| U3 매체 플러그인 개발자 | 플러그인 규약과 적합성 시험 키트 |

**SDK 품질 기준:** U2용 앱을 SDK **공개 API만으로** 만들 수 있어야 한다.

## 3. 요구사항 (가설, 인터뷰 후 갱신)

### W. 세계관 (World Kernel)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| W-01 | 세계관은 구조화된 문서다: 시각 언어, 존재(캐릭터·사물), 장소, 서사, 소리, 움직임, 금지 목록, 참고 자료 | Must |
| W-02 | 모든 영역은 선택 사항이다. 빈 세계관도 유효하다 (미니멀한 세계관은 적게 쓴다) | Must |
| W-03 | 버전 관리: 변경 이력, 이전 버전으로 생성 재현 | Must |
| W-04 | 갈래(fork)와 합성(두 세계관을 비율로 섞기) | Should |
| W-05 | 비영어 어휘와 고유 용어 사용 가능, 용어집 | Must |
| W-06 | 내보내기·가져오기 (사람이 읽을 수 있는 텍스트 형식) | Must |

### X. 스타일 축
| ID | 요구사항 | 우선순위 |
|---|---|---|
| X-01 | 기본 축: 밀도, 색, 형태, 질감, 소리, 움직임, 서사. 축마다 연속 값 | Must |
| X-02 | 작가·플러그인이 새 축을 정의 가능 | Should |
| X-03 | 복잡도 예산 (요소 수·색 수 상한)과 금지 목록이 생성기에 강제됨 | Must |
| X-04 | 축 값의 시간 변화(변형 경로)를 정의 가능 | Could |

### G. 생성기 플러그인 규약
| ID | 요구사항 | 우선순위 |
|---|---|---|
| G-01 | 모든 생성기: 세계관 + 의도 → 결과물 + 재현 레시피 | Must |
| G-02 | 공통 축을 자기 매체 파라미터로 번역하는 함수를 공개 (번역 결과를 작가가 보고 고칠 수 있게) | Must |
| G-03 | 결과물의 세계관 준수 정도를 자기 평가해 보고 | Should |
| G-04 | 다른 매체와 연결할 접점 공개 (예: 박자, 색 팔레트, 이벤트) | Should |
| G-05 | 적합성 시험 키트: 새 플러그인이 G-01~G-04를 지키는지 검사 | Must |

### M. 첫 매체 (나머지는 플러그인으로)
| ID | 매체 | 방식 | 우선순위 |
|---|---|---|---|
| M-01 | 2D 이미지 | 절차적 그래픽(기하·패턴) + AI 이미지 생성(원격 API, 공급자 **TODO**) | Must |
| M-02 | 사운드 | 절차적 합성(FM, 그래뉼러 등) | Must |
| M-03 | 인터랙션 | 웹 실시간 런타임: 마우스·카메라·소리 입력에 반응 | Must |
| M-04 | 3D | 절차적 형태 + 재질, glTF 내보내기 | Should |
| M-05 | 물리 작품 | ESP32 등 MCU 브리지(OSC/MQTT)로 서보·LED 구동 | Could |
| M-06 | 건축·공간 | 규칙 기반 파라메트릭 형태 | Could |

### C. 일관성
| ID | 요구사항 | 우선순위 |
|---|---|---|
| C-01 | 결과물이 자기 세계관을 따르는지 지표로 표시 (팔레트 이탈, 금지 요소, 복잡도 예산, 참고 자료와의 유사도) | Should |
| C-02 | 지표는 판정이 아니라 "검토 필요" 표시로만 쓴다. 최종 판단은 작가 | Must |

### E. 작가 통제와 탈출구
| ID | 요구사항 | 우선순위 |
|---|---|---|
| E-01 | 생성 결과를 직접 수정하고, 수정본을 다음 생성 입력으로 사용 | Must |
| E-02 | 작가 에셋(그림, 녹음, 3D) 가져오기 | Must |
| E-03 | 규칙 비활성화·무시 가능 | Must |
| E-04 | 어떤 단계든 사용자 코드로 대체 가능 (U1) | Should |

### R. 출처와 권리
| ID | 요구사항 | 우선순위 |
|---|---|---|
| R-01 | 모든 결과물에 재현 레시피 (세계관 버전, 생성기·모델 버전, 파라미터, 시드) | Must |
| R-02 | AI 사용 여부와 생성 이력을 C2PA 출처 정보로 기록 | Should |
| R-03 | 사용한 모델의 라이선스 추적, 상업적 사용 가능 여부 조회 | Should |
| R-04 | 세계관·참고 자료·학습 데이터는 작가 소유, 기본 비공개 | Must |

### T. 도구
| ID | 요구사항 | 우선순위 |
|---|---|---|
| T-01 | 세계관 편집기 (웹, 코드 없이) | Must |
| T-02 | 웹 플레이어: 이미지·사운드·인터랙션을 하나의 작품으로 재생, 전시용 전체 화면 | Must |
| T-03 | CLI와 Python·JavaScript API, 예제 | Must |

## 4. 아키텍처

```text
 U2 앱: 세계관 편집기 · 웹 플레이어 · (Could) 노드 편집기      ← 공개 API만 사용
 ─────────────────────────────────────────────────────────────
 SDK 공개 API (Python / JavaScript)
   World Kernel ── 스타일 축 ── 레시피·출처 ── 일관성 지표
   생성기 레지스트리 (플러그인 규약 G)
 ─────────────────────────────────────────────────────────────
 생성기 플러그인: 이미지(절차적 / AI) · 사운드 · 인터랙션 · 3D · 물리 · 건축 …
```

**세계관 형식 스케치** (값은 예시이며, 형식은 인터뷰 후 확정):

```yaml
world: "예시 — 흑백 미니멀"
version: 3
axes: {density: 0.05, color: 0.0, form: geometric, texture: 0.1, sound: 0.1, motion: 0.2}
budget: {max_elements: 3, max_colors: 2}
visual: {palette: ["#111111", "#F5F5F5"], references: ["ref/ink_01.png"]}
sound: {timbre: sine, tuning: just, silence_ratio: 0.7}
forbidden: ["gradient", "ornament"]
```

## 5. 검증: 표현력 시험 세트

서로 극단적으로 다른 **기준 세계관**을 정의하고, 시스템을 바꿀 때마다 전부 다시 통과시킨다.
기준 세계관 목록은 인터뷰한 작가들의 실제 세계관으로 교체·보강한다 (작가 동의를 받은 경우).

| ID | 검증 | 기준 |
|---|---|---|
| V-01 | 핵심 코드 수정 없이 표현 가능한 기준 세계관 수 | 전부 |
| V-02 | 새 매체 플러그인 추가 시 핵심 코드 변경 | 0줄 |
| V-03 | 미니멀 세계관의 복잡도 예산 위반 비율 | 측정 후 목표 설정 |
| V-04 | 세계관 구별성: 결과물이 자기 세계관을 따르고 다른 세계관과 구별되는가 (C-01 지표) | 측정 후 목표 설정 |
| V-05 | 재현성: 같은 레시피·같은 환경이면 같은 결과 | 불일치 0 (절차적), 지각적 차이 허용 범위 (AI) |
| V-06 | 플러그인 적합성 시험 (G-05) | 모든 기본 플러그인 통과 |
| V-07 | 실시간 성능: 입력 → 화면·소리 반응 지연, 오디오 끊김 | 측정 후 예산 고정 |
| V-08 | 실사용: 작가가 자기 세계관으로 2개 이상 매체 작품을 만들었는가, 걸린 시간, 막힌 지점 | 관찰 기록 |

## 7. 작가 인터뷰 계획

### 7.1 대상
- **"혁주 작업 공간"을 사용하는 작가들.**
- 확인 필요 (TODO):
  - 공간의 성격(작업실, 공유 스튜디오, 메이커스페이스, 온라인 공동체 등)
  - 작가 수
  - 주로 다루는 매체
  - 연락·섭외 방법
- **표본 다양성:** 다양성이 이 시스템의 핵심 목표라서, 스타일이 서로 다른 작가를 고른다. 가능하면 아래를 각 1명 이상 포함한다.
  - 미니멀 계열
  - 화려하거나 장식적인 계열
  - 사운드 또는 인터랙션 작업
  - 3D·공간 작업
- 공간의 작가들이 한쪽 스타일에 몰려 있으면 그 사실을 기록하고, 외부 작가로 보강할지 결정한다.
- 목표 인원: 3~5명.

### 7.2 진행 방식
- 1인 60분 내외, 작업 공간에서 실제 작업물을 보며 진행
- **동의:** 녹음 여부, 작품 사진 사용 여부, 이름 공개 여부를 시작 전에 따로 묻고 기록한다. 기본값은 비공개
- 인터뷰 결과에 작가의 미공개 작품이나 개인 정보를 담지 않는다

### 7.3 질문 가이드
1. **세계관:** 작품 밑에 깔린 "세계"가 있나요? 그걸 지금 어떻게 기록하고 관리하나요? (무드보드, 노트, 레퍼런스 폴더 등)
2. **매체 이동:** 같은 세계를 다른 매체로 옮겨 본 적이 있나요? 어디서 가장 막혔나요?
3. **일관성:** "이건 내 세계에 안 맞는다"고 느끼는 기준은 무엇인가요? 말로 설명할 수 있나요?
4. **도구:** 지금 쓰는 도구와, 그 도구에서 가장 시간을 많이 버리는 일은?
5. **AI:** AI 생성 도구를 써 봤나요? 쓰지 않는다면 이유는? (소유권, 화풍 모방, 결과의 획일성 등)
6. **규칙과 파괴:** 자기 세계관의 규칙을 일부러 깨는 경우가 있나요?
7. **협업과 공유:** 세계관을 다른 사람과 공유하거나 함께 만들어 본 적이 있나요?

### 7.4 관찰 과제
- 4절의 세계관 형식 초안을 보여 주고, 작가 본인의 세계관 일부를 이 형식으로 옮겨 보게 한다.
- 옮길 수 없었던 것, 형식이 강요한 것, 빠진 영역을 기록한다. **이것이 W·X 요구사항을 고치는 가장 직접적인 근거다.**

### 7.5 분석과 반영
- 인터뷰마다 요약(동의 범위 안에서)을 남기고, 공통 주제를 묶는다.
- 요구사항 변경은 "어느 인터뷰의 어떤 관찰 때문에"를 함께 기록한다.
- 인터뷰로 뒷받침되지 않은 요구사항은 Could로 내린다.

## 8. 위험

| 위험 | 대응 |
|---|---|
| "모든 예술"로 범위가 끝없이 늘어남 | 일반성은 인터페이스에, 첫 결과물은 매체 2~3개 + 극단적으로 다른 세계관 여러 개 |
| AI 생성기가 디테일을 더하는 쪽으로 기울어 미니멀을 망침 | 절차적 생성 우선, 복잡도 예산 강제(X-03), V-03으로 측정 |
| 개발자 혼자 정한 기준이 한쪽으로 치우침 | 기준 세계관을 작가들의 실제 세계관으로 교체, 문화권 고유 미학은 해당 전통을 아는 작가가 검토 |
| 작가들의 AI 거부감 | 작가 소유·비공개 기본(R-04), 생존 작가 모방 기능 미제공(P7), AI 없이 절차적 생성만으로도 쓸 수 있게 |
| 인터뷰 표본이 한 공간에 몰림 | 7.1의 다양성 확인, 필요 시 외부 보강 |
