# D2. Test Case 작성 가이드라인 (초안 v0.1)

> 근거 요건: [A10, A03]. 이 프로젝트의 모든 TC는 이 규칙을 따른다. 1~2절의 규칙은 CI가 검사한다.

## 1. ID와 태그

| 레벨 | 형식 | 예 |
|---|---|---|
| 단위 시험 (Unity, C) | 함수 `test_<검증하는 동작>` + 바로 위 주석 `/* @verifies SWR-NNN[, SWR-MMM] — 설명 */` | `test_signal_fault_debounce` |
| SIL 시험 (pytest) | `TC-<영역>-NNN` + `@verifies("SWR-NNN")` 데코레이터 | `TC-PROT-004` (6주차부터) |

- 하나의 TC는 하나의 SWR을 주로 검증한다. 여러 개를 달 때는 각 SWR의 판정 기준을 모두 확인해야 한다.
- 태그의 SWR ID는 `requirements/swr.yaml`에 존재해야 한다.
- 태그가 없는 시험은 허용하지 않는다. 시험 보조 함수는 `test_`로 시작하지 않게 이름 짓는다.
- 검사: `python tools/tc_tag_check.py`

## 2. 기대값 작성 규칙

1. **기대값은 요구사항 문장에서만 도출한다.** 구현을 한 번 돌려 나온 값을 기대값으로 쓰지 않는다. 그러면 결함이 기대값이 된다.
2. 수치 기준은 요구사항과 같은 단위·같은 기호로 쓴다. 상수를 쓸 때는 `bms_config.h`의 이름을 쓰되, 그 상수 값이 요구사항 문장과 같은지 검토에서 확인한다.
3. 시간 기준은 "N 샘플(N × 10 ms)"처럼 샘플 수와 시간을 함께 쓴다.
4. 요구사항이 판정 기준을 주지 않으면 기대값을 지어내지 않는다. 가정을 TC에 명시하고, 실패하면 "요구사항 모호"로 분류한다.

## 3. 요구사항 유형별 기법 선택

| 요구사항 유형 | 기법 | 최소 시험점 | 예 |
|---|---|---|---|
| 임계값 판정 (OV, UV, OT, 신호 범위) | 경계값 분석 | 임계값과 임계값 ± 1 LSB (양쪽 경계 모두) | SWR-002: 499 / 500 / 5000 / 5001 mV |
| 디바운스 (N회 연속) | 경계값 + 상태 전이 | N−1회(판정 안 됨), N회(판정됨), 중간에 정상 샘플이 끼는 경우(카운터 리셋) | SWR-004: 2회 → STANDBY, 3회 → FAULT, 교대 입력 → 고장 없음 |
| 상태 머신 | 상태 전이 | 모든 유효 전이 1회 이상, 금지된 전이 시도(예: FAULT에서 닫힘 요청), 래치 유지 | SWR-011, SWR-029 |
| 타임아웃 (통신) | 경계값 (시간) | 타임아웃 직전·직후, 수신 재개 | SWR-015: 290 ms / 300 ms / 310 ms |
| 카운터·체크섬 (E2E 개념) | 동등 분할 + 오류 추측 | 정상, 카운터 건너뜀, 카운터 반복, 15→0 롤오버, 체크섬 1비트 오류 | SWR-016, SWR-031 |
| 주기 송신 | 타이밍 측정 | 연속 N주기 측정, 최소·최대 간격이 허용 범위 안 | SWR-017: 100 ± 10 ms |
| UDS 서비스 | 긍정·부정 응답 | 서비스마다 긍정 1개 이상, 규정한 NRC마다 1개 | SWR-027: 0x11, 0x12, 0x13, 0x31 |
| 안전 반응 시간 | 결함 주입 + 타이밍 | 결함 주입 시각부터 출력까지 측정, 고장 종류마다 | SWR-010: ≤ 100 ms |

## 4. 증거 요구사항

- 단위 시험: CI 실행 기록(JUnit·ctest 로그)과 커버리지 리포트
- SIL 시험: `evidence/<TC-ID>/`에 입력 시나리오, 신호 트레이스, CAN 프레임 로그, 판정 결과. 실패 시 재현 명령 1줄
- 모든 증거에 커밋 해시를 남긴다 (`metrics.json`의 `commit`)

## 5. TC 검토 체크리스트

- [ ] 태그한 SWR의 판정 기준을 TC가 실제로 확인하는가
- [ ] 기대값이 요구사항 문장에서 나왔는가 (구현 출력에서 베끼지 않았는가)
- [ ] 3절의 최소 시험점을 모두 덮는가
- [ ] 실패했을 때 어느 요구사항이 깨졌는지 메시지로 알 수 있는가
- [ ] 다른 TC 결과나 실행 순서에 의존하지 않는가 (`setUp`에서 상태 초기화)
- [ ] 시간 의존 시험이 실제 시간이 아니라 시뮬레이션 시간을 쓰는가
